# 桌面端版本更新提示需求

## 背景

当前桌面端无任何更新通知机制。用户只能靠主动去官网查看或碰巧发现新版本。发布新版后，已安装用户的更新转化率极低，问题修复和新功能无法及时触达。

## 目标

在桌面端检测到新版本时，主动通知用户，并提供「去下载」入口。首版不做静默自动更新，用户自行完成下载和覆盖安装。

## 用户故事

1. 作为长期使用桌面端的用户，我希望在有新版本时第一时间收到通知，而不需要主动去找。
2. 作为觉得更新很麻烦的用户，我希望能关掉某个版本的弹窗提醒，不再被打扰。
3. 作为任何时候想检查更新的用户，我希望通过托盘菜单随时知道是否有新版本可用。

## 功能需求

### FR-1 启动检测

- 应用启动后延迟 **15 秒**执行首次版本检查（不阻塞主流程）
- 之后每 **24 小时**自动检查一次

### FR-2 版本比较

- 以 `latest.json` 中 `version` 字段与本地 `app.getVersion()` 做 semver 比较
- 只有 `latest > current` 时才触发通知流程

### FR-3 系统通知（Notification）

- 检测到新版本时弹出系统通知：
  - 标题：`AgentMemory`
  - 内容：`发现新版本 vX.Y.Z，点击前往下载页面`
- 用户**点击通知**：打开浏览器跳转到统一下载页
- 用户**关闭通知（叉掉）**：记录 `dismissedVersion = X.Y.Z`，重启后不再对该版本弹通知

### FR-4 托盘菜单条目

- 有待更新版本时，在托盘菜单**顶部**追加高亮条目：
  ```
  🆕 新版本 vX.Y.Z 可用 → 去下载
  ```
- 点击该条目：打开浏览器跳转到统一下载页
- 该条目持续显示，直到用户安装了新版本（即下次启动时 `latest === current`）

### FR-5 不再提示（dismissedVersion）

- 用户叉掉通知后，将该版本号写入本地配置 `dismissedVersion`
- 只影响通知弹窗，**不影响托盘菜单条目**（托盘仍作为被动提醒保留）
- 当检测到更新的新版本（版本号高于 dismissedVersion）时，重新弹通知

## 非目标

- 不做静默自动下载和安装
- 不做版本回退
- 不做强制更新拦截
- 不做应用内 Release Notes 展示（下载页自行承载）

## 验收标准

- [ ] 应用启动 15 秒后自动发起版本检查
- [ ] 检测到新版本时弹出系统通知
- [ ] 点击通知跳转到下载页
- [ ] 叉掉通知后重启不再弹同版本通知
- [ ] 托盘菜单顶部出现更新条目，点击跳转下载页
- [ ] 版本相同或本地更新时不触发任何通知
