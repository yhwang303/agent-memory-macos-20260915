# 桌面端连通性测试需求分析

## 背景

当前桌面端虽然已经支持在设置页中配置 AI provider，但用户保存后是否真的可用，只能靠启动 Worker 后查看日志或等实际记忆梳理触发，反馈路径过长。

在新增 `Claude Code / claude-internal` 可配置能力后，这个问题更明显：

- API 模式可能是 Key 错误、网络不通、模型不可用
- CLI 模式可能是命令不存在、路径写错、登录态失效

因此需要在桌面端设置页增加**连通性测试**能力，让用户在保存前直接验证。

## 目标

1. 用户可以在设置页点击“测试连通性”按钮，直接验证当前表单配置。
2. 支持所有 provider：
   - `TIMIAI`
   - `OpenAI`
   - `Anthropic`
   - `Claude Code`
3. 测试结果在界面上明确展示成功或失败原因。
4. 测试逻辑与实际运行链路保持尽量一致。

## 用户故事

1. 作为 API 用户，我希望在保存前确认我的 `API Key + 模型` 能正常调用。
2. 作为腾讯内网用户，我希望在输入 `claude-internal` 后，能一键确认本机命令可用且当前登录态正常。
3. 作为新用户，我希望看到明确错误提示，而不是只知道“不能用”。

## 功能需求

### FR-1 测试按钮

在桌面端设置页 `AI 配置` 区域新增：

- `测试连通性` 按钮

### FR-2 测试范围

#### API Provider

测试内容：

- 根据当前 provider、API Key、模型构造一次最小请求
- 发送简单 prompt，例如 `Reply with just "OK" to confirm connection.`
- 成功返回内容即视为通过

#### Claude Code Provider

测试内容：

- 根据当前 CLI 路径执行一次最小命令
- 验证命令可启动、可返回响应
- 成功返回内容即视为通过

### FR-3 结果展示

界面要展示：

- 测试中状态
- 成功提示
- 失败原因

示例：

- `连接成功：返回 OK`
- `连接失败：API Key 无效`
- `连接失败：找不到 claude-internal.cmd`

### FR-4 使用当前表单值

测试必须使用**当前页面输入值**，而不是只使用已经保存到本地配置的值。这样用户修改后无需先保存也能验证。

## 非目标

- 不做流式测试
- 不做复杂模型能力评估
- 不做自动安装或自动登录修复

## 验收标准

- [ ] 设置页出现 `测试连通性` 按钮
- [ ] API provider 可测试成功/失败
- [ ] `Claude Code` provider 可测试成功/失败
- [ ] 测试使用当前表单值，不要求先保存
- [ ] 失败时给出明确原因
