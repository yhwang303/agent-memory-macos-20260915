## 记忆处理结构全景

整个记忆系统的处理流程可以分为 **数据采集 → AI 提取 → 结构化存储 → 上下文注入** 四个阶段。

---

### 一、数据采集：利用了哪些数据？

数据来源是 **Cursor/CodeBuddy 的 Hooks 系统**（`hooks-cli.ts`），通过拦截 Agent 的各种事件来采集原始数据：

| Hook 事件 | 采集的数据 | 类型 |
|-----------|-----------|------|
| `beforeSubmitPrompt` | 用户输入的 prompt、workspace 路径 | 控制钩子 |
| `afterShellExecution` | 命令、输出、退出码、耗时 | 监控钩子 |
| `afterMCPExecution` | MCP 工具名、输入参数、返回结果 | 监控钩子 |
| `afterFileEdit` | 文件路径、diff 内容 | 监控钩子 |
| `afterSearchReplaceFileEdit` | 文件路径、old/new 字符串 | 监控钩子 |
| `afterAgentResponse` | Agent 回复的完整文本 | 监控钩子 |
| `afterAgentThought` | Agent 的思考内容 | 监控钩子 |
| `sessionEnd` / `stop` | 会话结束信号，触发摘要生成 | 生命周期钩子 |

### 三、两种记忆生成路径

**路径 1：Observation（实时观测）**

每次 Agent 执行工具时触发：

1. Hook 采集到原始数据（如 shell 命令 + 输出）
2. `SDKAgent.processObservation()` 根据数据类型选择 Prompt 模板：
   - `buildObservationPrompt()` — 通用工具操作
   - `buildResponsePrompt()` — Agent 回复
   - `buildThoughtPrompt()` — Agent 思考
3. 调用 LLM（默认 gpt-4o-mini）提取结构化信息
4. LLM 返回 XML 格式，`parseObservations()` 解析出：
   - `type`（discovery/bugfix/feature 等 9 种）
   - `title` + `subtitle`
   - `meta_intent`（元意图：用户做这件事的深层目的）
   - `facts`（可验证的事实列表）
   - `narrative`（叙述性描述）
   - `concepts`（概念标签）
   - `files_read` / `files_modified`
5. 写入 `observations` 表 + FTS5 索引

**路径 2：Summary（会话摘要）**

会话结束时触发（`stop` / `sessionEnd` Hook）：

1. 从数据库读取该会话的所有 observations（最多 20 条最近的）
2. 聚合所有文件操作记录
3. `buildSummaryPrompt()` 构建包含用户请求 + 所有观测的 Prompt
4. 调用 LLM 生成中文摘要
5. `parseSummary()` 解析出：
   - `request`（用户想做什么）
   - `investigated`（探索了什么）
   - `learned`（关键发现）
   - `meta_intent`（深层目的）
   - `completed`（完成了什么）
   - `next_steps`（后续建议）
6. 写入 `session_summaries` 表 + FTS5 索引

**路径 3：用户偏好检测（特殊路径）**

在 `beforeSubmitPrompt` 时额外触发：

1. 用户每次提交 prompt 时，调用 `detectPreferenceIntent()` 
2. LLM 判断是否包含稳定的个人偏好（如"我喜欢 VS Code"）
3. 如果检测到偏好，通过 `addDirectObservation()` **直接写入数据库**（不经过 AI 提取），避免信息丢失

---

### 四、上下文注入（记忆回放）

当新会话开始时（`beforeSubmitPrompt`），系统通过 `/api/context/inject` 读取数据库，将最近的 **3 条 session_summaries** 和 **10 条 observations** 组装成 XML 格式的 `additional_context`，注入到 Agent 的系统提示中，让 AI 能"记住"之前做过什么。

---

### 总结

简单说，整个系统就是：**Hook 采集原始操作 → LLM 提取结构化记忆 → SQLite + FTS5 持久化 → 下次会话注入上下文**。核心依赖 LLM 的能力来从杂乱的工具调用数据中提炼出有意义的"记忆"。
