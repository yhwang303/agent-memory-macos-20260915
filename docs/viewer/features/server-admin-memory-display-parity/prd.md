# server-admin-memory-display-parity — PRD

## 背景

记忆数据通过 `POST /api/v1/sync/*` 从客户端**原样**同步到服务端（`src/routes/sync.ts` 为纯透传 UPSERT，服务端无任何 LLM/二次理解）。也就是说同一条总结/会话/操作，两端存的字段文本是完全一致的。

但**展示方式不一致**：客户端 viewer（`agent-memory/web/viewer.html`）和服务端管理后台（`agent-memory-backend/web/admin.html`）对同一条记录，"卡片标题 / 预览 / 正文"取用的字段不同，导致用户在两个页面看到的"打头那段话"对不上，误以为内容被改写。

以「总结」为例，同一条 summary：

| 位置 | 客户端 viewer | 服务端 admin |
|------|---------------|--------------|
| 卡片标题 | `request`（用户想做什么） | `completed ‖ request`（实际显示 `completed`） |
| 卡片副标题/预览 | `completed ‖ learned` | `learned ‖ investigated` |

真实案例（同一条 summary）：

- 客户端标题：`用户想知道为什么两处看到的记忆数据"不一样"…`（= `request`）
- 服务端标题：`给出了差异产生的直接原因，说明了设备范围与聚合范围不同…`（= `completed`）

字段都在、都正确，只是**取来当标题的字段不同**，体验上像是"两份不一样的记忆"。

## 目标

让服务端管理后台「记忆」页（总结 / 会话 / 操作）对每条记录的**标题、预览、展开正文所取用的字段，与客户端 viewer 完全对齐**，使同一条记忆在两端"打头显示的内容"一致。

## 用户故事 / 使用场景

1. 作为同时用客户端 viewer 和服务端后台的用户，我希望同一条总结在两个页面里，标题展示的是同一段话（都是"用户想做什么"），一眼就能认出是同一条。
2. 作为排查同步问题的用户，我希望不用再怀疑"后端是不是把我的记忆重新理解了一遍"。
3. 作为浏览历史记忆的用户，我希望会话 / 操作卡片的标题、预览也和客户端口径一致。

## 范围

### 包含

- 仅改 `agent-memory-backend/web/admin.html` 中 `renderMem(item, type)` 对三类记录（summaries / sessions / observations）的**字段取用逻辑（标题 / 预览 / 正文）**，使之与 `viewer.html` 的卡片字段映射一致。
- 三类记录的字段映射对齐细节见 `design.md`。

### 不包含

- **不改**后端已有的标签行（账号名 / IDE / 设备 / 项目 / 时间）—— 这些是服务端聚合视图的有用信息，保留。
- **不要求**视觉样式（配色、卡片外观）逐像素一致；本需求只对齐"取哪个字段、显示哪段文字"。
- **不改**交互形态（admin 就地展开 vs viewer 弹窗）——可保留各自交互，只要展示的内容字段一致即可。
- **不涉及** ID 对齐、media_context 图片同步、跨账号范围过滤等其他差异（这些是独立议题，本需求不处理）。
- 不改任何同步 / 后端存储逻辑（数据本就一致）。

## 验收标准

- [ ] 同一条 summary，在 viewer 与 admin 卡片标题显示的是**同一字段**（`request`），文字一致。
- [ ] summary 预览 / 展开正文取用字段与 viewer 口径一致。
- [ ] session、observation 两类记录的标题 / 预览取用字段同样与 viewer 对齐。
- [ ] admin 原有标签行（账号 / IDE / 设备 / 项目 / 时间）保持不变。
- [ ] 字段为空时的兜底（fallback）行为与 viewer 一致，不出现 `undefined` / 空白标题。

## 风险与未决事项

- viewer 卡片只展示标题+副标题，完整字段在**弹窗详情**里；admin 是就地展开正文。需在 design 中明确：admin 展开正文沿用现有结构化分节（# 请求 / # 调研 …）还是对齐 viewer 详情弹窗的字段顺序。倾向于保留 admin 的结构化正文，仅对齐**标题与预览**字段。
- 文档与代码分属两个仓库（需求文档在 `agent-memory`，实现在 `agent-memory-backend`），需在 design 中标注跨仓改动点。
