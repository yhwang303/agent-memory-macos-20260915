# 用户偏好自动记忆需求分析

## 背景

当前记忆系统主要围绕 `Session`、`Observation` 和 `Summary` 记录编码过程中的操作与总结。
对于用户在对话中直接表达的明显偏好，例如“我喜欢吃清江鱼”“我不吃香菜”“我更习惯 Windows”，系统缺少一条稳定、低成本的自动记录链路。

同时，当前 `hooks-cli` 在 Windows + Cursor 场景下存在输入 JSON 带 BOM 时解析失败的问题，导致 `beforeSubmitPrompt`、`stop` 等关键 hook 无法正常执行，进一步影响用户输入的记录能力。

## 问题陈述

现状存在两个直接问题：

1. 用户偏好没有专门的结构化识别与落库能力。
2. hook 入口在部分输入下无法正确解析 JSON，导致即便设计了偏好识别逻辑，也无法稳定触发。

## 目标

本次优化目标如下：

1. 修复 `hooks-cli` 对 BOM 输入的兼容性，确保用户 prompt 能稳定进入系统。
2. 对“明显用户偏好”做轻量规则识别。
3. 对识别出的偏好直接写入 `observations`，不依赖 AI 模型权限。
4. 保持现有 `Session` / `Observation` / `Summary` 数据模型不变，尽量减少侵入性改动。

## 非目标

以下内容不在本次范围内：

1. 构建完整的用户画像系统。
2. 支持复杂语义推理下的隐式偏好识别。
3. 修改现有 Summary 生成策略。
4. 解决所有 observation 自动记录失败问题以外的模型权限问题。

## 典型场景

### 场景 1：饮食偏好

用户输入：

- “我喜欢吃清江鱼”
- “我爱吃辣”
- “我不吃香菜”

期望结果：

- 系统自动识别为明显偏好表达。
- 生成一条结构化 `Observation`。
- 后续可在 viewer / search / context 注入中使用。

### 场景 2：工作习惯偏好

用户输入：

- “我更习惯 Windows”
- “我喜欢用 pnpm”
- “我偏好简体中文回复”

期望结果：

- 只要表达足够直接明确，系统自动记录。

## 判定标准

本次“明显用户偏好”限定为：

1. 主语明确为用户自身，通常为“我”。
2. 谓词明确表达喜欢、偏好、习惯、不喜欢、不吃、不用等倾向。
3. 宾语清晰，不需要复杂上下文推断。

例如：

- “我喜欢吃清江鱼” => 应记录
- “清江鱼不错” => 暂不记录
- “这个方案我再想想” => 不属于偏好，不记录

## 方案要求

1. 必须优先保证稳定性，不能因为偏好识别影响现有 hook 主流程。
2. 必须避免依赖 AI 提取，否则会再次受到模型权限和超时影响。
3. 必须可回溯，落库内容要能清楚看出来源于用户原始 prompt。
4. 对重复表达的相同偏好，尽量避免短时间内连续生成完全重复记录。

## 验收标准

1. `beforeSubmitPrompt` 在 BOM 输入下可以正常解析。
2. 输入“我喜欢吃清江鱼”后，系统自动新增一条 `Observation`。
3. 该记录可在 `viewer` 中看到，内容包含偏好事实与原始用户表达。
4. 未命中规则的普通问句不应误生成偏好记录。
