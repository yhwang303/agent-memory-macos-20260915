# self-evolve 内容操作 vs 规范约束 判别门禁 — prd

## 1. 背景

self-evolve 会从会话里自动提炼 rule / skill。当前它**只读 AI 压缩后的 observation（`narrative`/`facts`/`title`）+ session summary**，看不到原始对话，导致：

- 不知道"前因后果"：例如规则「删除副本时保留原始生成内容」里的"副本"到底指什么、用户在哪个操作语境下说的，模型一概不知。
- 把**一次性的内容/代码处置**（针对某次具体产物/文件的临时决定）误判为**长期遵守的项目规范**，沉淀成 `工作流规范` 类规则。
- prompt 的 Q1 要求"必须引用用户原话"，但管线里根本没有原话字段，`evidence` 填的是 AI 转述，门禁形同虚设。

存量已出现误判规则（mem-1780「删除副本时保留原始生成内容」即典型）。

## 2. 需求目标

让 self-evolve 在生成 rule 前能区分两类完全不同的输入，并只把后者沉淀为规则：

- **目标 1**：新增「内容/代码操作 vs 规范约束」判别维度——针对某次具体产物/文件/任务的一次性处置一律**不生成规则**。
- **目标 2**：强制 `evidence` 为用户**逐字原话**；纯 AI 转述/二手摘要一律拒绝。
- **目标 3**：复核并归档存量误判规则（先处理 mem-1780）。
- **目标 4（增强项，可后置）**：observation 生成链路保留关键用户原话片段，让原话校验有真实数据来源。

## 3. 非目标

- 不重构 observation/summary 数据模型（目标 4 之外）。
- 不改变 rule/skill 的存储结构与审核流程（reviewMode / quality gate 保持不变）。

## 4. 验收标准


| 编号  | 标准                                                                                                      |
| --- | ------------------------------------------------------------------------------------------------------- |
| AC1 | 输入一段"一次性内容/文件处置"语境的 observation 时，self-evolve 不再生成 `工作流规范` 类规则（输出空 rule_actions 并在 analysis 说明被判为一次性操作） |
| AC2 | `evidence` 字段若非逐字原话（疑似转述/摘要），该规则被拒绝或不生成                                                                 |
| AC3 | 存量 mem-1780 规则被归档（status=deprecated），不再注入上下文                                                            |
| AC4 | 既有正常规则（真实跨会话偏好/规范）不被误杀——回归对比通过                                                                          |


## 5. 待确认问题

- 「原话校验」由 prompt 侧约束即可，还是需要在 `EvolveEngine` 落地一道程序化校验（如 evidence 必须能在 observation 文本中找到子串）？
- 目标 4 是否本期实现，取决于是否接受改动 observation 生成 prompt。
