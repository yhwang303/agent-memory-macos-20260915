# PRD：服务端管理后台与多用户 Token 分发

> 版本: 1.0.0
> 最后更新: 2026-04-19
> 状态: 草案
> 关联 PRD: PRD-cross-device-memory-sync.md

---

## 一、背景与动机

### 1.1 现状

`agent-mem-server` 已实现跨设备记忆同步与汇总（见 `PRD-cross-device-memory-sync.md`），但鉴权模型为**单一共享 Token**（`SHARED_TOKEN` 环境变量）：

- 所有客户端共用同一个 Token
- 服务端不区分数据归属，所有记忆都堆在一起
- Token 只能通过运维手动改环境变量来轮换
- 没有任何后台界面，部署后只能通过 SQL 看数据

### 1.2 痛点

1. **Token 分发依赖运维**：用户拿到服务地址后还得问管理员要 Token，管理员要改 env 重启
2. **多人共用一台服务器无法隔离**：家人 / 同事 / 朋友合用一台 NAS 时，所有人记忆混在一起，互相能看到
3. **Token 一次泄露全员中招**：单一 Token 一旦泄露要全部客户端重新配置
4. **运维盲区**：管理员看不到"哪些用户在用、各占多少存储、最近一次同步时间"等运营数据
5. **无后台**：服务端目前是纯 API，没有 Web 页面入口（按照"复用客户端 viewer"的设计），但管理员需要的"用户管理 / 全局统计"等功能客户端 viewer 是给不出来的

### 1.3 需求来源

来自当面交流：

> 用户真正使用只要一个客户端和服务端（服务端还支持自己部署到自己服务器），然后客户端配置连接服务器并同步数据到服务器上。还是得给服务端增加一个简易用户管理端，并且分发自己的 token（因为用户得给客户端配置连接服务器的验证 token），用户可以查看整个数据的存储情况或者在服务器上直接查看记忆数据，页面风格和原客户端保持一致。

## 二、目标用户与角色

| 角色 | 描述 | 技术水平假设 | 使用入口 |
|:---|:---|:---|:---|
| **管理员（Admin）** | 服务器部署者本人 | **小白**：会用宝塔面板、会跟教程 `docker run`，但**不会**改环境变量、不懂 SQL、不愿打开终端 | 管理后台 `/admin` |
| **用户（User）** | 拿到 Admin 分发的 Token 后用于客户端同步 | **更小白**：希望"装个软件就好"，不想看任何 `.env` 文件 | 客户端 Desktop App / IDE 内 |
| **客户端（Client）** | 持有 User Token 的设备 / IDE | 自动行为，无人工 | 通过 `Authorization: Bearer <user_token>` 访问 sync API |

> 当前阶段 User 不区分角色权限，只要持有合法 Token 即视为该 Token 所属用户。
>
> **核心体验目标**：参照宝塔面板的体验标准——**全程鼠标点点点完成配置，不出现任何"请打开终端 / 编辑 .env 文件 / 复制粘贴长串"等操作**。

## 三、用户场景

### 场景 1：自部署后首次创建账户

> 小明在自家 NAS 上 `docker run` 启动 agent-mem-server。打开浏览器访问 `http://nas:8848/admin`，看到登录页。用初次部署时配置的 `ADMIN_PASSWORD` 登录后，进入后台。点击「新建用户」→ 填写"小明的 Mac"→ 系统生成一个 Token。复制这个 Token，去 Mac 上的 agent-memory 客户端 `.env.local` 里填上 `CODEBUDDY_MEM_REMOTE_TOKEN=...`，sync 立刻生效。

### 场景 2：给家人分配独立账户

> 小明的妻子也想用这个服务存自己的工作记忆。小明在后台再创建一个用户 "wife"，生成一个新 Token 给她。她把 Token 配到自己电脑客户端，开始同步。两人的数据在数据库里通过 `user_id` 完全隔离，互相看不到对方记忆。

### 场景 3：吊销泄露的 Token

> 小明发现自己的 Mac Token 不小心截图发到群里了。他打开后台 → 找到该 Token → 点「吊销」。被吊销的 Token 立即失效，所有持有它的客户端 sync 请求收到 401。小明在 Mac 上重新生成一个新 Token，重新配置即可。已经同步上去的历史数据保留不变。

### 场景 4：管理员全局看板

> 小明想知道服务跑得怎么样。打开后台首页：
> - 总用户数、总设备数、总会话/总观察/总总结条数
> - 数据库文件大小
> - 每个用户最近一次同步时间、各自数据量
> 一眼就能看出谁在用、谁停了。

### 场景 5：管理员浏览某个用户的记忆

> 小明想回顾妻子允许他看的某段工作（或者排查某个用户的同步问题）。后台「数据浏览」tab 选中目标用户，看到的就是熟悉的客户端 viewer 风格的列表（Sessions / Observations / Summaries），可以按项目、设备、IDE 过滤。

### 场景 6：用户自己访问后台只看自己的数据（可选 P1）

> 用户拿到 Token 后，也可以直接访问 `http://nas:8848/admin`，输入自己的 Token（不是 Admin 密码）登录，进入只读模式：只能看到自己的数据，不能管理用户。

### 场景 7：管理员首次启动「初始化向导」

> 小明 `docker run` 起来后第一次访问 `http://nas:8848`，**没有任何配置**。页面自动跳到「初始化向导」：
>
> 1. **Step 1 — 设置管理员密码**：输入两次密码（带强度提示）→ 下一步
> 2. **Step 2 — 创建第一个账号**：默认填了一个名字 `me`，点「创建」直接生成 Token
> 3. **Step 3 — 配置我的客户端**：页面显示「邀请链接」+ 二维码 + 三种连接方式（一键邀请 / 手动复制 / Docker 客户端命令），并给出「客户端还没装？点这里下载」按钮
>
> 全程没有让小明打开过终端、编辑过任何文件。

### 场景 8：客户端「一键接入」秒级配置

> 小明在 Mac 上装好 agent-memory Desktop App。打开后看到一个「连接到服务器」按钮，他点击后有两种方式：
>
> - **方式 A：粘贴邀请链接** — 把后台生成的 `cmem://connect?...` 链接贴进去，App 自动解析地址 + Token，测试连接后写入配置，30 秒内完成接入
> - **方式 B：扫码** — 用手机/相机扫描后台显示的二维码（链接同上），App 监听到 cmem:// 协议唤起后自动配置
>
> 小明全程没有看过 Token 长什么样，也没有动过任何 `.env` 文件。

### 场景 9：客户端 GUI 设置页管理连接

> 小明换了一台机器或想改服务器地址。打开 Desktop App → 设置 → 「服务器连接」分页：
> - 显示当前服务器地址、当前账号名、连接状态（绿色"在线"/红色"断开"/橙色"重连中"）
> - 显示队列状态：积压 N 条 / 已同步 N 条 / 失败 N 条
> - 「测试连接」按钮 / 「断开」按钮 / 「换一个服务器」按钮
> - 失败时显示带颜色的"具体错在哪"提示（不是裸 stack trace）
>
> 整个过程不需要打开 `.env.local`，连"环境变量"四个字都看不到。

### 场景 10：老客户端首次连接服务器，自动补传历史数据

> 小明的 Mac 上 agent-memory 已经独立用了 3 个月，本地 SQLite 累积了 5 个会话、3000 条观察、80 条总结。今天他刚部署好服务端，在 Mac Desktop App 粘贴邀请链接接入服务器。
>
> 接入瞬间：
> - 顶部状态徽章变绿"已连接"
> - 下面立刻出现一行进度条：「正在补传历史数据：0 / 3085 条…」
> - 进度条实时跳数，预计剩余时间会显示
> - 大约 1-3 分钟后变为"补传完成 ✅"
> - 同时管理后台「记忆」Tab 立刻能看到这台 Mac 之前 3 个月的全部历史
>
> 小明全程没有点过任何"开始补传"按钮，没有跑过命令，没有意识到"补传"这个概念存在 —— 它是自动发生的副作用。
>
> 中途若网络中断或他关电脑，下次打开 App 自动从断点继续，不重发已经发送过的。

### 场景 11：管理员后台一键操作零术语

> 小明在「用户」Tab 里看每行卡片上的按钮文字：
> - **不是**「Rotate Token / Revoke Token / DELETE User」
> - **而是**「换一把新钥匙 🔑 / 暂停这个账号 ⏸ / 删除这个账号 🗑」
>
> 任何破坏性操作都有"说人话"的二次确认弹框，例如：
> - "重新生成钥匙后，旧钥匙立即失效，所有用旧钥匙的设备需要重新配置。继续吗？"
> - "删除 alice 将会永久清除她的 50 个会话、3000 条记忆。此操作不可恢复，请输入用户名 `alice` 以确认。"

## 四、功能性需求

### FR-1：管理员登录

- FR-1.1：服务端通过环境变量 `ADMIN_PASSWORD` 配置管理员密码（首次启动若未配置则在日志输出一个随机生成的初始密码）
- FR-1.2：管理后台登录页 `GET /admin`：表单输入密码 → `POST /api/v1/admin/login` → 服务端比对成功后下发 `admin_session_token`（随机 64 字符，存内存 Map，默认 7 天有效）
- FR-1.3：客户端将 `admin_session_token` 存于浏览器 `localStorage`，后续所有 admin API 通过 `Authorization: Bearer <admin_session_token>` 携带
- FR-1.4：`POST /api/v1/admin/logout` 可主动注销 session

### FR-2：用户与 Token 管理

- FR-2.1：管理员可创建用户：填写 `name`（必填，唯一）+ 可选 `note`
- FR-2.2：创建用户时自动生成一个**初始 Token**（32 字节随机），创建结果**仅在响应中返回一次明文**，之后只能看到 Token 的 `last 8` 显示
- FR-2.3：管理员可查看用户列表：name / note / 创建时间 / 最近同步时间 / 设备数 / 数据量
- FR-2.4：管理员可吊销 Token（不可逆，不删除历史数据）
- FR-2.5：管理员可重新生成 Token（旧 Token 立即失效，新 Token 返回一次明文）
- FR-2.6：管理员可删除用户（连同其所有同步数据物理删除，需二次确认）

### FR-3：数据隔离

- FR-3.1：服务端 `sessions` / `observations` / `summaries` / `devices` 表新增 `user_id` 列
- FR-3.2：所有 `POST /api/v1/sync/*` 请求根据 `Authorization` 中的 Token 反查 `user_id`，写入数据时打上归属
- FR-3.3：所有 `GET /api/v1/aggregate/*` 与 `/api/v1/viewer/*` 请求支持 `user_id` 过滤参数
- FR-3.4：未携带 Token 或 Token 无效的同步请求返回 401
- FR-3.5：客户端 viewer 远端模式访问 `/api/v1/viewer/*` 时，同样使用 `Authorization: Bearer <user_token>`，服务端只返回该 user 的数据

### FR-4：管理后台界面

- FR-4.1：HTML 单页应用 `GET /admin`，风格与客户端 `web/viewer.html` 保持一致（紫色渐变 header、卡片式列表、Tab 切换）
- FR-4.2：登录后顶部 4 个 Tab：
  - **概览（Overview）**：全局统计 + 数据库大小 + 最近活跃用户
  - **用户（Users）**：用户列表 + 创建/吊销/重生成/删除
  - **记忆（Memory）**：与客户端 viewer 一致的 Sessions / Observations / Summaries 三个子 Tab，加一个「用户筛选」下拉
  - **设置（Settings）**：当前 Admin Token、过期时间、注销按钮、重置 Admin 密码入口
- FR-4.3：所有列表支持按 user / project / ide / 日期过滤
- FR-4.4：数据卡片样式和客户端 viewer 完全一致（同样的颜色、布局、徽章），让用户/管理员有"在哪都一样"的体验

### FR-5：管理 API

- FR-5.1：`POST /api/v1/admin/login`
- FR-5.2：`POST /api/v1/admin/logout`
- FR-5.3：`GET /api/v1/admin/overview` 返回全局统计
- FR-5.4：`GET /api/v1/admin/users` 用户列表
- FR-5.5：`POST /api/v1/admin/users` 创建用户（返回明文 Token 一次）
- FR-5.6：`POST /api/v1/admin/users/:id/rotate-token` 重新生成 Token
- FR-5.7：`POST /api/v1/admin/users/:id/revoke` 吊销当前 Token
- FR-5.8：`DELETE /api/v1/admin/users/:id` 删除用户及其数据（需 `?confirm=1`）
- FR-5.9：所有 admin API 需 `Authorization: Bearer <admin_session_token>` 鉴权
- FR-5.10：admin API 与 user sync API 路径前缀清晰区分（`/api/v1/admin/*` vs `/api/v1/sync/*`）

### FR-6：向后兼容（SHARED_TOKEN 模式）

- FR-6.1：若启动时检测到 `SHARED_TOKEN` 环境变量且数据库中无任何用户，则自动创建一个 `name=default` 的用户，把 `SHARED_TOKEN` 作为该用户的初始 Token，并把现有未归属的数据全部 `user_id` 指向 default
- FR-6.2：旧客户端使用 `SHARED_TOKEN` 直接访问，不需要任何变更
- FR-6.3：新部署若同时配置 `ADMIN_PASSWORD` 和 `SHARED_TOKEN`，两套都生效（Admin 走密码，客户端走 SHARED_TOKEN）

### FR-7：用户只读模式（可选 P1）

- FR-7.1：用户也可以在 `/admin` 登录页用「User Token」选项登录
- FR-7.2：登录后只能看到自己的数据，无法访问 Users / Settings tab
- FR-7.3：可在自己的「我的 Token」页查看 Token 状态、生成时间、最近使用时间

### FR-8：服务端「初始化向导」（傻瓜化关键）

- FR-8.1：服务首次启动若未配置 `ADMIN_PASSWORD` 且 `admin_config` 表为空，访问根路径 `/` 或 `/admin` 自动跳到 `/admin/setup`
- FR-8.2：向导分 3 步且**不可跳过**：
  1. 设置管理员密码（带强度提示：长度/大小写/数字）+ 二次确认
  2. 创建第一个用户账号（默认建议名 `me` 或 `default`）
  3. 显示该账号的邀请链接 / 二维码 / 复制按钮 / 客户端下载入口
- FR-8.3：向导完成后写入 `admin_config` + 创建首个 user + token，跳到管理后台
- FR-8.4：向导每一步都有"这一步在做什么"的小图标提示
- FR-8.5：服务运行中重启不会再次触发向导（除非 admin_config 为空）

### FR-9：邀请链接 / 二维码 / 自定义协议

- FR-9.1：管理员在「用户」Tab 点击「📋 邀请链接」按钮，弹框显示：
  - **邀请链接**：`cmem://connect?server=http%3A%2F%2Fnas%3A8848&token=xxx&user=alice`
  - **二维码**（同链接，用 `qrcode` 纯前端库生成 SVG，零依赖）
  - **手动配置**（折叠显示）：服务器地址、Token 明文、可复制
- FR-9.2：邀请链接默认包含**当前 active token 明文**，仅在生成/重生成的 5 分钟内有效查看（过后链接里 token 字段消失只显示地址，强制重生成）
- FR-9.3：客户端 Desktop App 注册系统级 `cmem://` URL Scheme，点击 / 扫码 / 粘贴均可触发自动配置流程
- FR-9.4：自动配置流程：解析 → 测试 GET `/health` → 测试 sync token（GET `/api/v1/viewer/projects`，401 则提示 token 错误，200 则 OK）→ 写入配置 → 重启 worker → toast 提示"已成功连接到 nas:8848（账号 alice）"

### FR-10：客户端 Desktop GUI 配置（傻瓜化关键）

- FR-10.1：Desktop App 设置窗口新增「服务器连接」分页，包含：
  - 当前连接状态徽章（在线 / 断开 / 重连中 / 未配置）
  - 服务器地址、账号名、Token 后 8 位（不显示完整 token）
  - 「测试连接」按钮（实时反馈）
  - 「断开」按钮（清空 token，停止 sync）
  - 「使用邀请链接重新连接」按钮（同 FR-9.4 流程）
  - 同步队列实时状态：pending / sent / failed 三个数字 + 「立即同步」按钮 + 「清空失败重试」按钮
- FR-10.2：Desktop 托盘菜单（TrayManager）新增「同步状态」子菜单，鼠标悬停显示最近同步时间和积压数
- FR-10.3：用户全程不需要查看或编辑 `.env.local`；该文件由 Desktop App 写入和管理
- FR-10.4：连接失败时，错误提示用大白话：
  - 网络不通 → "连不上服务器，请检查地址是否正确，或服务器是否已开机"
  - Token 错误 → "钥匙不对，可能是被管理员重置了，请联系管理员要新的邀请链接"
  - 地址协议错 → "地址应该以 http:// 或 https:// 开头"

### FR-11：历史数据自动补传

> 解决场景 10：老客户端积累了大量本地数据后才接入服务器。

- FR-11.1：客户端 Worker 启动 / 重连服务器时，**自动**扫描本地 SQLite 中所有 `synced_at IS NULL` 的 sessions / observations / summaries 入队补传，**不需要用户点任何按钮**
- FR-11.2：补传与新增数据同走 `SyncQueue`，使用相同的幂等 / 重试 / 退避机制，重复执行不会产生重复数据
- FR-11.3：补传过程中产生的新数据正常入队，**不阻塞**新数据的同步（队列按 FIFO + 优先级处理：新数据优先级高于补传）
- FR-11.4：Desktop App「服务器连接」分页显示**补传专属进度卡片**：
  - 总数 / 已传 / 剩余 / 预计剩余时间
  - 实时进度条（百分比）
  - 完成后变成"补传完成 ✅"提示，30 秒后自动收起
- FR-11.5：管理后台「概览」页对每个用户显示「最近 24 小时新增 N 条 / 总计 M 条」，让管理员看到补传进度
- FR-11.6：补传中网络中断 / App 关闭 → 下次启动自动断点续传（基于 `synced_at IS NULL` 的扫描），不会重复传送已成功的
- FR-11.7：用户可在 Desktop 设置页手动触发「重新检查未同步数据」按钮（兜底），用于排查"是不是有遗漏"

### FR-12：管理后台「零术语」UI

- FR-12.1：所有破坏性操作的按钮文字使用大白话 + 表情符号（见场景 11）
- FR-12.2：所有二次确认弹框给出"做了会怎样、能不能撤销"的明确说明
- FR-12.3：删除用户必须二次输入用户名以确认（防止手滑）
- FR-12.4：每个 Tab 顶部有一行小灰字简介（如"在这里管理可以连接服务器的账号和钥匙"）
- FR-12.5：所有可复制内容（链接、Token、地址）都有 📋 一键复制按钮，复制后变 ✅ 反馈 2 秒
- FR-12.6：管理员后台所有时间显示「3 分钟前 / 2 小时前 / 昨天」相对时间，不显示长串 ISO timestamp

## 五、非功能性需求

### NFR-1：安全

- 密码校验使用 `crypto.timingSafeEqual` 防时序攻击
- Token 在数据库中以 `sha256(token + salt)` 形式存储，明文只在创建/重生成时返回一次
- Admin 密码不写明文，存储 `bcrypt(password)` 或 `sha256(password + salt)`（首版用 sha256，后续可升级 bcrypt）
- HTTPS 由用户自行通过反代解决（服务端不内置 TLS）
- Admin session 默认 7 天过期，敏感操作（删除用户）要求最近 5 分钟内重新输入密码（P2）

### NFR-2：兼容

- 数据库升级走 `ALTER TABLE ADD COLUMN`，不破坏现有数据
- 老的 `SHARED_TOKEN` 模式保留至少 1 个大版本
- 客户端无需任何代码改动，只是 Token 的来源从"管理员手发"变成"管理员后台生成"

### NFR-3：体验（傻瓜化标准）

- 后台页面**复用客户端 viewer 的视觉风格**：紫色渐变 header、相同的圆角卡片、相同字体、相同标签徽章
- 单页应用，无后端模板，HTML/CSS/JS 三件套，零构建
- 所有破坏性操作（吊销、删除）二次确认 + 大白话说明 + 严格输入校验
- 创建用户后明文 Token 提供一键复制按钮，并明确告知"此 Token 只显示一次，请立即保存"
- **零终端**：除了一次 `docker run`（或宝塔面板里点装），管理员和用户后续操作不需要打开任何命令行
- **零文本配置**：用户不需要编辑任何 `.env` / `.json` / `yml` 文件
- **零黑话**：UI 中不出现 "Token / Bearer / Hash / Salt / Migration" 等技术词；底层概念用"钥匙 / 账号 / 数据库大小"等替代
- **零等待迷茫**：所有异步操作有 loading 状态 + 超时兜底 + 失败可重试

### NFR-4：可达性

- 后台 UI 在 1280×720 分辨率最小可用
- 所有按钮可键盘 Tab 聚焦
- 错误信息中文优先（沿用现有客户端的中文 UI 风格）

### NFR-5：部署

- 仍然 `docker run` 一行启动
- 新增可选环境变量 `ADMIN_PASSWORD`，未配置时**进入向导让用户在浏览器里设置**（不再依赖日志找密码）
- 不引入数据库迁移工具，schema 自动 `ALTER` 兼容

## 六、MVP 范围（Phase 1）

### 包含

- 管理员密码登录 + session token
- **服务端首次启动初始化向导**（FR-8）
- 用户 CRUD + Token 生成/吊销/重生成
- **邀请链接 + 二维码 + cmem:// 协议**（FR-9）
- 数据库 schema 增量：sessions/observations/summaries/devices 加 `user_id`
- sync API 改造：根据 Token 反查 user_id 并打上归属
- viewer/aggregate API 加 `user_id` 过滤
- 管理后台 HTML 单页（4 个 Tab + 向导页）
- **客户端 Desktop 设置页「服务器连接」分页**（FR-10）
- **客户端 cmem:// URL Scheme 注册与处理**（FR-9.3）
- **历史数据自动补传 + 进度展示**（FR-11）
- **零术语 UI**（FR-12）
- SHARED_TOKEN 自动迁移为 default 用户
- 复用客户端 viewer 的视觉样式

### 不包含（后续阶段）

- 用户自注册 / 密码找回 / 邮箱验证
- 用户只读模式（FR-7）放到 P1
- 角色权限分级（Admin / Reader / Writer）
- 操作审计日志
- 多 Admin / 团队管理
- bcrypt / argon2 密码哈希（先用 sha256+salt）
- 操作频率限制 / IP 白名单
