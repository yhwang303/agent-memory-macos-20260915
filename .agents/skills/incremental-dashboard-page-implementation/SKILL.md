# 增量式仪表盘页面实现与验证

## 1. 准备阶段

1. 扫描目标页面及其相关资源，确认当前页面结构、组件分层、样式组织方式。
2. 明确本次任务是“在现有基础上新增功能”，避免推翻式重写。
3. 提炼现有页面的可视化层次，例如：顶部标签/导航、概览统计区、图表区、列表区、详情展开区等。
4. 将拟新增功能映射到现有结构中，说明哪些区域复用、哪些区域扩展、哪些交互需要补充。
5. 在动手修改前，先向用户展示页面结构方案或变更草图，等待确认。

## 2. 执行阶段

1. 基于现有页面做增量修改，优先复用已有布局、样式和交互模式。
2. 若页面属于仪表盘/查看器类场景，优先保持以下设计原则：
   - 上半部分展示概览信息（统计卡片、分布、趋势）
   - 下半部分展示可操作内容（列表、开关、详情、状态）
   - 状态差异通过视觉样式明确体现，如灰化、禁用、折叠/展开
3. 修改页面文件时，确保新增功能不会破坏既有功能与信息层次。
4. 如涉及交互控件（开关、展开项、标签切换），同步补齐必要的数据绑定和状态渲染逻辑。
5. 完成页面改动后，执行项目的构建、编译或预览流程，确认页面能正常产出。

## 3. 验证阶段

1. 检查页面结构是否与确认方案一致。
2. 检查新增功能是否是“增量扩展”而非破坏性替换。
3. 检查关键可视区块是否完整：
   - 导航/标签
   - 统计概览
   - 图表或趋势区
   - 列表及详情区
   - 状态样式表现
4. 执行构建或编译后，确认无报错，产物可用。
5. 向用户汇报结果时，摘要说明：改了哪些区域、保留了哪些原有结构、如何验证通过。

## 协作协议

1. 先扫描相关文件，收集上下文
2. 展示发现和计划，等待用户确认
3. 执行操作前征得用户同意
4. 完成后展示结果摘要
