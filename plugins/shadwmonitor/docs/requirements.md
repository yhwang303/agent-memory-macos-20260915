# AI Monitor - 屏幕活动感知系统 需求分析文档

## 1. 项目概述

### 1.1 项目目标
构建一个本地运行的屏幕数据捕获与智能分析系统，自动记录用户全天电脑使用行为，通过多层感知架构将原始屏幕数据逐级蒸馏为可读的行为摘要，同时支持按时间索引进行渐进式披露查询。

### 1.2 核心价值
- **自动化记录**：无需手动操作，后台自动捕获屏幕活动
- **智能理解**：通过 OCR + LLM 将像素级数据转化为语义级理解
- **渐进式披露**：从日摘要 → 时段摘要 → 时刻详情，按需逐层展开
- **隐私安全**：全部数据存储在本地，不上传任何截图或文本

## 2. 系统架构总览

```
三层感知架构：

┌─────────────────────────────────────────────────┐
│           Agent 感知层 (智能蒸馏)                  │
│  L3: 日摘要 ← L2: 时段摘要 ← L1: 时刻描述         │
│  支持渐进式披露：日 → 时段 → 时刻 → 原始数据        │
└──────────────────────┬──────────────────────────┘
                       │ 读取 OCR 结构化数据
┌──────────────────────▼──────────────────────────┐
│           OCR 感知层 (文本提取)                    │
│  截图 → OCR引擎 → 空间结构化文本 → 存储            │
└──────────────────────┬──────────────────────────┘
                       │ 提供截图
┌──────────────────────▼──────────────────────────┐
│           系统感知层 (数据采集)                     │
│  前台窗口监控 + OpenCV屏幕变化检测 + 截图           │
└─────────────────────────────────────────────────┘
```

## 3. 功能需求

### 3.1 系统感知层

#### FR-1: 前台窗口监控
- **FR-1.1**: 实时获取当前前台活动窗口的进程名称和窗口标题
- **FR-1.2**: 窗口切换时记录切换事件（时间戳、旧窗口、新窗口）
- **FR-1.3**: 定时轮询间隔 ≤ 1秒，确保不遗漏快速切换

#### FR-2: 屏幕变化检测
- **FR-2.1**: 使用 OpenCV 对比前后两帧截图的差异
- **FR-2.2**: 差异度超过可配置阈值时触发截图保存
- **FR-2.3**: 截图采样间隔可配置（默认 2 秒对比一次）
- **FR-2.4**: 即使无变化，也按可配置最大间隔（默认 60 秒）强制截图一次，防止长时间静止场景丢失
- **FR-2.5**: 截图保存为 PNG 格式，按日期目录组织

#### FR-3: 元数据记录
- **FR-3.1**: 每次截图时记录：时间戳、前台窗口名、进程名、截图路径、变化度评分
- **FR-3.2**: 所有元数据写入本地数据库

### 3.2 OCR 感知层

#### FR-4: 文本提取
- **FR-4.1**: 对每张变化截图执行 OCR，提取文本及其在屏幕上的位置（bounding box）
- **FR-4.2**: 支持中英文混合识别
- **FR-4.3**: OCR 可异步执行，不阻塞截图流程

#### FR-5: 空间结构化文本存储
- **FR-5.1**: 将屏幕划分为区域网格（如 4列×3行 = 12个区域）
- **FR-5.2**: 将 OCR 结果按 bounding box 中心点映射到对应区域
- **FR-5.3**: 生成紧凑的空间结构化文本表示（Zone-Map 格式），示例：
  ```
  @1920x1080 [WeChat.exe: 微信] 2026-04-14T10:30:00
  [TL] 聊天列表 | 张三 | 李四 | 工作群
  [TC] 张三: 你好，明天开会吗？ / 我: 好的，几点？
  [BL] (空)
  [BC] 输入框: _
  [TR][BR] (空)
  ```
- **FR-5.4**: Zone-Map 格式设计目标：保留空间结构、可读性高、token 数量最小化
- **FR-5.5**: 将 Zone-Map 文本存入数据库，同时保留原始 OCR bbox 数据用于精确回溯

### 3.3 Agent 感知层

#### FR-6: L1 - 时刻描述（Moment Summary）
- **FR-6.1**: 对每个 5 分钟时间窗口内的 Zone-Map 数据调用 LLM，生成 1-2 句话描述"此刻用户在做什么"
- **FR-6.2**: 输入：该窗口内所有截图的 Zone-Map + 窗口名称
- **FR-6.3**: 输出示例："用户在微信与张三讨论明天的会议安排"
- **FR-6.4**: 存入数据库并关联对应的原始截图 ID 列表

#### FR-7: L2 - 时段摘要（Session Summary）
- **FR-7.1**: 将连续使用同一类应用的多个 L1 描述聚合为一个时段
- **FR-7.2**: 或按固定时间窗口（如 30 分钟）聚合
- **FR-7.3**: 调用 LLM 将多个 L1 描述蒸馏为一段时段摘要
- **FR-7.4**: 输出示例："10:00-10:30 用户在微信处理多个工作沟通，包括与张三讨论会议安排、在工作群确认项目进度"

#### FR-8: L3 - 日摘要（Daily Summary）
- **FR-8.1**: 每日结束时（或手动触发），将所有 L2 时段摘要聚合
- **FR-8.2**: 调用 LLM 生成日报式的活动总结
- **FR-8.3**: 包含时间分配统计（各类应用使用时长占比）

#### FR-9: 渐进式披露查询
- **FR-9.1**: 支持从 L3 → L2 → L1 → 原始数据的逐层下钻
- **FR-9.2**: 每层通过时间范围索引关联上下层
- **FR-9.3**: 查询某一时刻时，可直接定位到对应的 L1 描述及其关联截图

## 4. 非功能需求

### 4.1 性能
- **NFR-1**: 截图对比延迟 < 100ms（不含截图本身）
- **NFR-2**: CPU 占用 < 5%（非 OCR 时段）
- **NFR-3**: OCR 处理不阻塞截图采集流程

### 4.2 存储
- **NFR-4**: 截图按日期自动归档，支持配置自动清理策略（如保留最近 N 天）
- **NFR-5**: 数据库单日数据量预估：~500 次截图 × 2KB Zone-Map ≈ 1MB 文本数据

### 4.3 可配置性
- **NFR-6**: 截图间隔、变化阈值、OCR 引擎、LLM API 等均通过配置文件管理
- **NFR-7**: 支持配置排除的应用（如密码管理器、银行网站等隐私场景）

### 4.4 可靠性
- **NFR-8**: 程序崩溃后重启可自动恢复，不丢失已捕获数据
- **NFR-9**: OCR 或 LLM 服务不可用时，原始截图和元数据仍正常保存

## 5. 技术选型建议

| 组件 | 技术方案 | 理由 |
|------|----------|------|
| 编程语言 | Python 3.10+ | 生态丰富，OpenCV/OCR/LLM 库完备 |
| 截图 | mss | 跨平台、高性能截图库 |
| 屏幕对比 | OpenCV (SSIM/absdiff) | 成熟的图像对比方案 |
| 窗口信息 | pywin32 (Windows) | 原生 Windows API 调用 |
| OCR 引擎 | PaddleOCR | 中英文识别准确，返回 bbox 位置 |
| 数据库 | SQLite | 轻量、本地、无需部署 |
| LLM 调用 | OpenAI API 兼容接口 | 灵活适配各类模型 |
| 配置管理 | YAML | 可读性好，层级结构清晰 |

## 6. 数据流概览

```
[屏幕] 
  │ mss 截图 (每2秒)
  ▼
[OpenCV 对比] ──无变化──→ 跳过
  │ 有变化
  ▼
[保存截图] + [记录元数据(窗口名、时间、路径)] → SQLite
  │
  ▼ (异步)
[PaddleOCR] → bbox + text
  │
  ▼
[Zone-Map 生成器] → 空间结构化文本 → SQLite
  │
  ▼ (定时 / 按需)
[L1 蒸馏: 时刻描述] → SQLite    ← 5分钟窗口
  │
  ▼
[L2 蒸馏: 时段摘要] → SQLite    ← 30分钟/应用切换
  │
  ▼
[L3 蒸馏: 日摘要]   → SQLite    ← 每日一次
```

## 7. 用户交互场景

### 场景1：查看日报
用户："今天我都干了什么？"
→ 返回 L3 日摘要

### 场景2：时段下钻
用户："上午 10 点到 11 点我在做什么？"
→ 返回该时段的 L2 摘要列表

### 场景3：时刻详情
用户："10:15 那会儿微信在聊什么？"
→ 返回 L1 时刻描述 + 可选展示 Zone-Map 原始文本

### 场景4：原始数据回溯
用户："给我看 10:15:30 的截图"
→ 返回对应截图文件路径 / 显示截图
