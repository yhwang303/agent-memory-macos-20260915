# 08 · 发布脚本被测试失败 + 脏工作区拦住

## 现象
- `npm run release` / `build-mac.sh` 跑到一半被卡住：
  1. 工作区有未跟踪文件（worker-node-modules 下大量 SDK 临时产物），脚本拒绝继续。
  2. `tests/server/viewer-api.test.ts` 里的断言写死了 `API_BASE`，但生产配置改用动态端口/域，导致测试挂掉，发布被打断。

## 解决（短期）
- 用环境变量临时跳过：
  ```bash
  RELEASE_ALLOW_DIRTY=1 RELEASE_SKIP_TESTS=1 ./build-mac.sh
  ```
- 这样能完成本次发版，DMG 正常产出。

## 解决（长期）
- 把 `worker-node-modules` 加进 `.gitignore`，构建脚本自己生成而不入版本库。
- 修复 `viewer-api.test.ts`：从配置/环境读 `API_BASE`，而不是 hard-code，避免和真实运行时漂移。

## 教训
- "跳过测试发布"是应急手段而不是常态，必须把根因记下来排进修复列表。
- 发布脚本要把"工作区脏"和"业务测试失败"分级提示，不能一刀切都阻塞。
